====================================================================
 Buckshot Roulette 黑色霰弹模组 —— 制作与校验报告
====================================================================

【环境】
  游戏版本 : Buckshot Roulette v2.2.0.6 (Steam, AppID 2835570)
  引擎     : Godot 4.1.1 (custom_build bd6af8e0e)
  资源     : 全部打包在 "Buckshot Roulette.exe" 内嵌的 PCK 中
             （PE 节 "pck"，PCK v2，3572 个文件，GDScript 为明文 .gd）

--------------------------------------------------------------------
一、改动内容
--------------------------------------------------------------------
  新增“黑色霰弹”（第三种弹种），修改 7 个单机脚本：

  1) ShellSpawner.gd      回合开始时按 BLACK_SHELL_CHANCE = 0.5 追加 1 发 "black"；
                          仅当回合内有红+蓝弹时追加；第一回合不追加（每回合最多 1 发）；
                          生成弹壳、播报文本追加 "  +1 BLACK"
  2) ShellBranch.gd       弹仓托盘里的黑色外观（运行时复制 live 材质并调暗）
  3) ShellEjectManager.gd 退壳时的黑色外观
  4) ShellExamine.gd      放大镜检查时的黑色外观
  5) ShotgunShooting.gd   玩家开枪：黑弹打自己/庄家 → 血量强制归零 → 走原版死亡/胜利流程
  6) DealerIntelligence.gd 庄家开枪同样处理；AI 的“已知弹种”推理把黑弹视作实弹
  7) ItemInteraction.gd   转换器只翻转红/蓝，黑弹保持不变

  美术资源：0 个文件被新增/修改/删除。

--------------------------------------------------------------------
二、校验结果
--------------------------------------------------------------------
  [1] 原始资源完整性
      从 exe 解包 3572 个文件，逐个 MD5 与 PCK 记录比对：3572/3572 全部一致。

  [2] 脚本解析
      用游戏自带的 Godot 4.1.1 实际加载 7 个修改后的脚本，
      启动日志无任何 "Parse Error / SCRIPT ERROR"，可正常进入主场景。

  [3] 黑色霰弹实测（单人模式）
      · 弹仓托盘中出现明显黑色的弹壳，数量比“红+蓝”多 1
      · 开局播报："1 LIVE ROUND. 2 BLANKS.  +1 BLACK"
      · 运行日志确认弹仓序列： ["black", "live", "blank", "blank"]

  [4] 一击必杀逻辑
      黑弹命中时执行与实弹完全相同的命中/死亡流程，只是把目标血量强制置 0：
        · 打自己：health_player = 0 → DeathManager.Kill("player") → OutOfHealth → 死亡场景
        · 打庄家：health_opponent = 0 → DeathManager.Kill("dealer") → OutOfHealth → 赢下回合
      庄家回合同理。血量归零即触发原有死亡/胜利流程，不依赖伤害数值。

  [5] 安装器 / 卸载器健壮性（在独立 exe 副本上实测）
      · 自动定位：通过注册表 SteamPath + libraryfolders.vdf 扫描所有 Steam 库，
        找不到时可拖拽游戏目录或命令行传参
      · 版本校验：安装前比对 7 个脚本的原始 MD5（v2.2.0.6），
        版本不符会拒绝安装并提示，不会把不同版本改坏
      · 幂等：重复安装会提示 "already installed"，不会重复追加
      · 写入后回读校验：7/7 与模组文件逐字节一致（md5 一致）
      · 卸载安全：卸载前校验当前表项确实等于“本模组写入的值”，
        不符（例如游戏更新过）则拒绝执行且不做任何修改
      · 实测循环：install → "Verified OK"；再次 install → already installed；
        uninstall → 恢复 7/7 表项；再次 uninstall → 拒绝且文件未变

  [6] 多人模式隔离
      只替换单机 scripts/ 下 7 个文件；多人使用 multiplayer/scripts/ 独立脚本，
      完全未修改，联机不会出现黑弹。

--------------------------------------------------------------------
三、已知说明
--------------------------------------------------------------------
  · 模组通过修改 exe 内嵌 PCK 实现；Steam“验证游戏文件完整性”会还原官方版本。
  · 游戏更新后需重新运行 install.bat（版本号变化时安装器会拒绝并提示）。
  · 自动键鼠测试环境不稳定，“黑弹一枪清空血量”的最终确认以代码路径 +
    实机弹仓/播报验证为准，未录制逐帧击杀对比视频。
  · 卸载后 exe 会比原始体积大（追加的数据留在文件尾部，不再被引用），
    不影响游戏；想完全还原可用 Steam 验证文件完整性。

四、补充校验（分享版安装器，v1.0 final）
--------------------------------------------------------------------
  [a] 自动定位：本机游戏库后来被移动到 H:\SteamLibrary，
      install.bat 不带参数运行仍能通过注册表 + libraryfolders.vdf 自动找到，
      并正确识别为“已安装”（幂等）。
  [b] 拖拽/传参安装：以 install.bat "<游戏目录>" 方式安装成功并回读校验通过。
  [c] 版本保护：把某个脚本的表项 md5 改成未知值模拟“其它版本”，
      安装器拒绝执行并打印：
        "These game scripts are from a different game version ... 
         This mod was built for Buckshot Roulette v2.2.0.6 / build 16736575."
      未对游戏做任何修改。
  [d] 文件被占用（游戏运行中）时会给出明确提示，而不是直接报底层异常。
  [e] 重复安装 → "Mod is already installed - nothing to do."
      卸载 → 恢复 7/7；再次卸载 → 拒绝且不改动文件。
